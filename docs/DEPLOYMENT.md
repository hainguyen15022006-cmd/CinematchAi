# Deployment

CineMatch is deployed as two separate services:

| Part | Where | Why |
|---|---|---|
| Frontend (React + Vite) | Vercel, free Hobby plan | A built Vite app is static files; Vercel serves them well and gives automatic HTTPS and preview URLs. |
| Backend (FastAPI + PyTorch) | Render, free plan, from the Dockerfile | The API loads a PyTorch model and writes to a database, which a serverless function cannot do. |

The Frontend cannot host the Backend. A Vercel Hobby function is limited to
250 MB and has a read-only filesystem, while PyTorch alone is larger than
that and SQLite needs to write. The two parts therefore talk over HTTPS and
are configured through environment variables on both sides.

## 1. What the Backend ships with

`artifacts/serving/` is committed on purpose and is about 645 KB:

| File | Purpose |
|---|---|
| `mf_checkpoint.pt` | Trained MF model used for scoring. |
| `train_ratings.csv.gz` | Train-only ratings for the cold-start fold-in. |
| `id_mappings.json` | MovieLens ID to model index translation. |
| `movies.csv.gz` | Catalog used to seed an empty database. |

A deployment therefore never downloads MovieLens or runs the data pipeline.
Rebuild the bundle after retraining:

```bash
python scripts/build_serving_bundle.py
python scripts/build_serving_bundle.py --checkpoint outputs/baselines/gmf_checkpoint.pt
```

## 2. Deploy the Backend to Render

1. Push this branch to GitHub.
2. Render dashboard, **New** -> **Blueprint**, pick the repository and this
   branch. Render reads `render.yaml` and creates the `cinematch-api`
   service from the `Dockerfile`.
3. Set `BACKEND_CORS_ORIGINS` once the Frontend URL exists, as a JSON list:

   ```
   ["https://your-site.vercel.app"]
   ```

   `SECRET_KEY` is generated by Render. `BACKEND_CORS_ORIGIN_REGEX` already
   allows Vercel preview URLs.
4. Wait for the first build. It installs the CPU-only PyTorch wheel, which
   takes several minutes.
5. Check the service:

   - `https://<service>.onrender.com/health` returns `{"status":"ok"}`
   - `https://<service>.onrender.com/recommend/status` returns
     `{"available": true, "model": "mf", ...}`
   - `https://<service>.onrender.com/docs` shows the API

If `/recommend/status` reports `available: false`, the serving bundle did
not reach the image. Check that `artifacts/serving/` is committed and that
`.dockerignore` does not exclude it.

### What the free plan costs you

- **The service sleeps after 15 minutes of inactivity.** The next request
  wakes it and takes roughly a minute while PyTorch loads. Open the API
  URL before a demo.
- **512 MB of memory.** With the CUDA build of PyTorch this project needs
  about 607 MB, which is why the `Dockerfile` installs the CPU-only wheel
  instead. If the service is still killed for memory, move to a paid plan
  or to Railway, which gives more memory on its free credit.
- **The disk is wiped on every deploy.** The movie catalog is seeded again
  automatically on startup, but accounts, rooms and votes are lost. Use a
  managed Postgres for anything you want to keep, see below.

### Optional: keep accounts between deploys

1. Create a free database, for example on Neon or Supabase.
2. Add `psycopg` to the image by changing the `Dockerfile` line to
   `RUN pip install -e ".[postgres]"`.
3. Set `DATABASE_URL` on Render:

   ```
   postgresql+psycopg://user:password@host:5432/dbname
   ```

The tables are created on startup and the catalog is seeded once.

## 3. Deploy the Frontend to Vercel

1. Vercel dashboard, **Add New** -> **Project**, import the repository.
2. Set **Root Directory** to `frontend`. Vercel then reads
   `frontend/vercel.json` and detects Vite automatically.
3. Add an environment variable, for Production and Preview:

   ```
   VITE_API_BASE_URL = https://<service>.onrender.com
   ```

   No trailing slash. Vite inlines this value at build time, so changing it
   later requires a redeploy, not just a restart.
4. Deploy, then put the resulting URL into `BACKEND_CORS_ORIGINS` on Render
   and redeploy the API.

`vercel.json` rewrites every path to `index.html`. Without that rule a
refresh on `/rooms/ABC123/runs/7` returns 404, because only the React
router knows that address.

## 4. Check the deployment

Open the Vercel URL and walk through the flow:

1. Register two accounts, in a normal window and a private window.
2. Rate at least one movie with each account. Scoring needs a profile, and
   a member without ratings is rejected with a clear message.
3. Create a room with the first account, join with the code from the
   second, mark both ready.
4. The host picks a strategy and starts the Top-K.
5. Both vote, the host closes voting, both see the same winner.

If the browser console shows a CORS error, `BACKEND_CORS_ORIGINS` does not
contain the exact Frontend origin, including `https://`.

## 5. Running the same stack locally

```bash
# Backend
cp .env.example .env
uvicorn app.main:app --reload

# Frontend
cd frontend
cp .env.example .env.local
npm install
npm run dev
```

The Backend seeds the catalog by itself on first start. `.env.example`
already allows `http://localhost:5173`.

To test the production build locally, run `npm run build` and
`npm run preview`, then add `http://127.0.0.1:4173` to
`BACKEND_CORS_ORIGINS`.
